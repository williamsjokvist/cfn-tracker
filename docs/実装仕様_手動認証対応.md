# 実装仕様 — SF6 認証で画像認証(CAPTCHA)が出た場合の手動対応

対象ブランチ: `fix/resilient-tracking`
前提コミット: `835795b`（通信断対応・ldflags 修正まで完了済み）

---

## 0. 背景と方針

SF6 のトラッキング開始時、CapID へのログインで **画像認証(CAPTCHA)** が出るようになった。
その結果、認証が進捗 50% で止まり、**アプリが何も表示せずに固まる**。

実機で確認した事象:

```
auth-progress 10 → 30 → 50 で停止。以降ログも UI も一切変化しない。
```

### やること / やらないこと（★厳守）

- **やらない: CAPTCHA を自動で突破すること。**
  画像認証の自動解答、外部の CAPTCHA 解答サービスの利用、
  ボット検知回避（`go-rod/stealth` の強化・User-Agent やフィンガープリントの偽装追加）は
  **一切行わない**。既存の `stealth.MustPage` はそのまま残すが、手を加えない。
- **やる: 人間が自分で解けるようにして、解き終わるまで待つ。**
  画像認証は「人間であることを確認する」ための仕組みであり、
  人間が自分のアカウントに対して手で解くのは正規の使い方である。
  現状はそれすら**できない**（後述の理由）ので、できるようにする。
- **やる: 待っている間、何が起きているかを画面に出す。**
  黙って固まるのをやめる。これは本プロジェクトの一貫した方針。

## 1. 直す欠陥

### 1-1. 画像がブロックされていて CAPTCHA が表示されない（★根本原因）

`app/pkg/browser/browser.go:47-62` のリクエストハイジャッカが
**全画像・全フォント・（steam 以外の）全 CSS をブロック**している。

```go
if ctx.Request.Type() == proto.NetworkResourceTypeImage ||
    ctx.Request.Type() == proto.NetworkResourceTypeFont {
    ctx.Response.Fail(proto.NetworkErrorReasonBlockedByClient)
    return
}
```

帯域節約のための最適化だが、**CAPTCHA の画像もこれで落ちる**。
そのため `HEADLESS=false` にしてブラウザを表示しても、
画像認証が表示されず**人間にも解けない**。

### 1-2. リダイレクト待ちが無限ループ

`app/pkg/tracker/sf6/cfn/client.go:120-131`。

```go
statChan <- *status.WithProgress(50)
var secondsWaited time.Duration = 0
for {
    if !strings.Contains(page.MustInfo().URL, "auth.cid.capcom.com") {
        break
    }
    time.Sleep(time.Second)      // 上限なし・ctx を見ない・進捗を出さない
    secondsWaited += time.Second
    slog.Debug("bypassing cfn auth gateway...", ...)
}
```

上限も `ctx` 監視も無く、待機中の通知も無い。ログも `slog.Debug` なので既定では出ない。

### 1-3. `SelectGame` が `range` で無限に待ちうる

`app/cmd/tracking.go` の `SelectGame` は `for status := range authChan` で受けている。
`Authenticate` が値を送らず・チャネルも閉じずに止まると、**ctx がタイムアウトしても抜けない**
（`range` はチャネルが閉じられるまで終わらないため）。

## 2. 修正仕様 A — アセットブロックを切り替え可能にする

**対象: `app/pkg/browser/browser.go`**

1. `Browser` 構造体に以下を追加する。
   ```go
   type Browser struct {
       Page         *rod.Page
       HijackRouter *rod.HijackRouter
       Headless     bool          // 呼び出し側が headless か判断できるようにする
       blockAssets  atomic.Bool   // ハイジャッカが別 goroutine で走るため atomic
   }
   ```
2. `NewBrowser(headless bool)` を、**先に `b := &Browser{Headless: headless}` を作り、
   `b.blockAssets.Store(true)` してから**、`b` を参照するハイジャッカを登録する形に変える。
3. 公開メソッドを追加する。
   ```go
   // SetAssetBlocking は画像・フォント・CSS のブロックを切り替える。
   // 画像認証を人間が解く場面では false にする必要がある。
   func (b *Browser) SetAssetBlocking(enabled bool)
   ```
4. ブロック判定を**純粋関数に切り出す**（テスト可能にするため）。
   ```go
   func shouldBlockRequest(t proto.NetworkResourceType, hostname string, blocking bool) bool
   ```
   - `blocking == false` のときは**常に false**（何もブロックしない）
   - `blocking == true` のときは現在の挙動を維持
     （Image / Font はブロック、Stylesheet は hostname に `steam` を含まなければブロック）
   ハイジャッカ本体はこの関数を呼ぶだけにする。

**既定値は `true`**（＝現在の帯域節約の挙動を維持）。ポーリング中の通信量を増やさない。

## 3. 修正仕様 B — 認証中だけブロックを外し、待機を有界にして通知する

**対象: `app/pkg/tracker/sf6/cfn/client.go` の `Authenticate`**

### B-1. 認証中はアセットを通す

`Authenticate` の冒頭（`c.browser == nil` チェックの直後）で
`c.browser.SetAssetBlocking(false)` し、`defer c.browser.SetAssetBlocking(true)` で必ず戻す。
認証が終われば元の節約モードに戻る。

### B-2. 定数

```go
const (
    authGatewayWaitHeadless = 30 * time.Second // 人が介入できないので早く諦める
    authGatewayWaitManual   = 5 * time.Minute  // 人が手で解く時間
    authGatewayPollInterval = 1 * time.Second
)
```

### B-3. リダイレクト待ちループの置き換え

`statChan <- *status.WithProgress(50)` の直後のループを以下の仕様にする。

- 待機上限は `c.browser.Headless` が true なら `authGatewayWaitHeadless`、
  false なら `authGatewayWaitManual`。
- 毎秒ループし、**毎回 `statChan` に「操作待ち」ステータスを送る**（形式は仕様 C）。
  - headless のとき: `localizationKey = "authNeedsHeadful"`
  - headful のとき: `localizationKey = "authSolveCaptcha"`
  - `SecondsLeft` に残り秒数を入れる
- `ctx.Done()` を必ず監視する。`time.Sleep` ではなく
  `select { case <-ctx.Done(): ...; case <-time.After(authGatewayPollInterval): }` を使う。
- URL が `auth.cid.capcom.com` を含まなくなったら break（成功。従来どおり）。
- 上限に達したら **エラーとして報告して return する**。エラーは
  `localizationKey` を持つ形にし、headless なら `errAuthNeedsHeadful`、
  headful なら `errAuthManualTimeout` を使う。
  ログには**現在の URL も出す**（原因究明に必要。認証情報は絶対に出さない）。
- ログは `slog.Debug` ではなく `slog.Info` にする（既定のログレベルで見えるように）。

### B-4. 例外

`page.MustInfo()` は rod の Must 系なので ctx 失効時に panic する。
既存の `defer recover()` がそれを拾って `statChan` にエラーを送る構造は維持する。

## 4. 修正仕様 C — 「操作待ち」を UI に届ける

### C-1. `tracker.AuthStatus` の拡張

**対象: `app/pkg/tracker/tracker.go`**

```go
type AuthStatus struct {
    Progress int
    Err      error
    Action   *AuthAction // nil なら通常の進捗通知。非 nil なら人間の操作待ち
}

type AuthAction struct {
    LocalizationKey string `json:"localizationKey"`
    SecondsLeft     int    `json:"secondsLeft"`
}

func (s *AuthStatus) WithAction(key string, secondsLeft int) *AuthStatus
```

既存の `WithProgress` / `WithError` は**シグネチャも意味も変えない**。

### C-2. `SelectGame` の修正

**対象: `app/cmd/tracking.go`**

1. **`range` をやめ、`ctx.Done()` と併せた `select` で受ける**（1-3 の修正）。
   チャネルが閉じられなくても ctx で必ず抜けられるようにする。
2. `status.Action != nil` のときは **`auth-progress` を発火せず**、
   新イベント `auth-action-required` に `*status.Action` を載せて発火する。
   進捗値は更新しない（50% のまま据え置き）。
3. それ以外は従来どおり `auth-progress` を発火し、100 以上で終了。
4. タイムアウトを延ばす。定数化すること。
   ```go
   const selectGameTimeout = 7 * time.Minute // authGatewayWaitManual(5分) を上回る必要がある
   ```
   **60 秒のままでは人間が CAPTCHA を解き終わる前に切れる。**

> 既存イベント `auth-progress` の名前・ペイロード形式は**変えない**（後方互換）。
> 追加するのは `auth-action-required` のみ。

### C-3. フロントエンド

**`app/gui/src/state/auth-machine.ts`**
- context に `action: { localizationKey: string; secondsLeft: number } | null` を追加（初期値 null）
- `subscribeToProgressEvents` に `EventsOn('auth-action-required', ...)` を追加し、
  `unsubscribeToProgressEvents` に対応する `EventsOff` を**必ず**追加する
- 受信時は `loading` 状態に留まったまま context.action を更新するだけ
- `finished` / `error` で `action: null` に戻す

**`app/gui/src/pages/tracking/index.tsx`**
- `authState === 'loading'` の分岐で、`action` が非 null なら
  `t('loading')` の代わりに `t(action.localizationKey, { seconds: action.secondsLeft })` を表示する。
- 加えて、**操作を促す注意書きを目立つ形で常時表示**する
  （画像認証はブラウザの別ウィンドウに出るので、本体側に案内が無いと気づけない）。

**i18n `app/pkg/i18n/locales/{en-GB,ja-JP,fr-FR}.json`（3ファイルすべて）**

| キー | ja-JP |
|---|---|
| `authSolveCaptcha` | 別ウィンドウのブラウザで画像認証を解いてください（残り {{seconds}} 秒） |
| `authNeedsHeadful` | 画像認証が表示されました。ヘッドレスのままでは操作できません |
| `errAuthNeedsHeadful` | 画像認証が必要です。`.env` の HEADLESS を false にして起動し直し、ブラウザ画面で認証を完了してください |
| `errAuthManualTimeout` | 画像認証が時間内に完了しませんでした。もう一度お試しください |

en-GB / fr-FR にも妥当な訳を入れること。

## 5. 受入条件（自動テスト）

ブラウザ実体を要する部分は自動化しない。**純粋関数と制御フローだけを対象にする。**
`app/pkg/browser/browser_test.go` と `app/cmd/tracking_test.go` に以下を追加する。

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | `TestShouldBlockRequest` | `blocking=true` で Image/Font/Stylesheet がブロックされ、steam の Stylesheet は通ること。**`blocking=false` ではすべて通ること** |
| 2 | `TestSelectGameEmitsAuthActionRequired` | `Action` 付きステータスを送るフェイクで `auth-action-required` が発火し、`auth-progress` は発火しないこと |
| 3 | `TestSelectGameReturnsOnAuthError` | `Action` を数回送った後にエラーを送るフェイクで、`SelectGame` が有限時間でエラーを返すこと |
| 4 | **`TestSelectGameDoesNotHangWhenChannelNeverCloses`** | **値を送らずチャネルも閉じないフェイクでも、`SelectGame` が ctx により有限時間で戻ること（1-3 の回帰テスト）** |

テスト4が本タスクの本丸。テストでは待ち時間短縮のため、
`SelectGame` が使うタイムアウトをテストから差し替えられるようにしてよい
（例: パッケージ変数にして `_test.go` から上書き）。**7 分待つテストは書かないこと。**

既存テスト（`TestTrackingSelectGame` および通信断対応で追加した9件）を**1件も壊さないこと**。
特に `TestTrackingSelectGame` は SF6 選択時に
`"unauthenticated: browser not initialized"` を期待している。この文言を変えないこと。

## 6. 検証コマンド

作業ディレクトリは `app/`。**`./...` は使わない**（root の `main` だけが Wails を import しており
Linux では GTK/WebKit ヘッダが要るため必ず失敗する）。

```bash
export GOMODCACHE=/tmp/gomodcache
export GOCACHE=/tmp/gocache
cd app
gofmt -l ./cmd ./pkg          # 出力が空であること
go build ./cmd/... ./pkg/...
go vet   ./cmd/... ./pkg/...
go test  ./cmd/... ./pkg/... -count=1
```

## 7. 禁止事項

- **CAPTCHA の自動突破に類する実装を一切しない**（0章参照）。
  既存の `stealth` 呼び出しには手を加えない。新たな回避ライブラリを導入しない。
- `wails build` / `bun install` / `npm install` / `bunx` / `npx` を実行しない。
- `app/main.go` を変更しない。
- 新規の外部依存を追加しない（`go.mod` / `package.json` を変更しない）。
- 認証情報を**ログにもテストにも出さない**。URL は出してよいがクエリに認証情報が
  含まれる可能性がある場合は出さない。
- 既存イベント名（`auth-progress` / `match` / `stopped-tracking` /
  `tracking-retrying` / `tracking-recovered` / `tracking-error`）の名前と形を変えない。
- 仕様書に無いリファクタリングをしない。
- 改行は LF 固定。
