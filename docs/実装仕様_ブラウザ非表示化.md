# 実装仕様 — ブラウザを画像認証のときだけ表示する

対象ブランチ: `fix/resilient-tracking`
前提コミット: `6d9591e`

---

## 0. 背景と目的

`app/main.go:163` が起動直後に `browser.NewBrowser(cfg.Headless)` を呼ぶため、
`HEADLESS=false` にしていると **アプリを起動しただけで Chromium のウィンドウが出る**。
画像認証を手で解くには `HEADLESS=false` が必要なので、現状は
「認証のために常時ウィンドウが出っぱなし」になっている。

配信用ツールとしてこれは不適切（配信画面に映り込む）。

**目標**: 通常はウィンドウを一切出さず、**画像認証で人間の操作が要るときだけ表示する。
解き終わったら再び消す。**

Chromium のヘッドレスは**起動時にしか決められない**（実行中に切り替える API は無い）。
したがって切り替えは「閉じて起動し直す」で実現する。

---

## 1. 変更後の振る舞い

`HEADLESS` は「ユーザーが望む既定モード」を表す設定とし、既定は `true`。

| 場面 | ウィンドウ |
|---|---|
| アプリ起動時 | **出ない**（ヘッドレスで起動） |
| セッションが生きていて認証が即完了 | **出ない** |
| 画像認証などで人間の操作が要ると判明した時 | **表示ありで起動し直し、ウィンドウを出す** |
| 認証完了後 | **ヘッドレスで起動し直し、ウィンドウを消す** |
| `HEADLESS=false`（切り分け用） | 最初から最後まで**出したまま**。起動し直しもしない |

`HEADLESS=false` は「常に見せるデバッグモード」として温存する。

## 2. 修正仕様 A — ブラウザを起動し直せるようにする

**対象: `app/pkg/browser/browser.go`**

現状 `NewBrowser` はローカル変数で launcher と rod.Browser を作り捨てており、
後から閉じることができない。閉じて起動し直せる形にする。

```go
type Browser struct {
    Page         *rod.Page
    HijackRouter *rod.HijackRouter
    Headless     bool // 現在のモード
    // PreferHeadless は利用者が設定した既定モード。
    // 画像認証のために一時的に表示ありへ切り替えた後、ここへ戻る。
    PreferHeadless bool

    mu          sync.Mutex // 起動・停止・付け替えの排他
    blockAssets atomic.Bool
    launcher    *launcher.Launcher
    rod         *rod.Browser
}
```

1. `NewBrowser(headless bool) (*Browser, error)`
   - シグネチャは変えない（`main.go` を変更しないため）
   - `PreferHeadless` と `Headless` の初期値に `headless` を入れ、`launch(headless)` を呼ぶ
2. `func (b *Browser) launch(headless bool) error`（非公開）
   - 現在の `NewBrowser` の中身をここへ移す。launcher と rod.Browser を構造体に保持する
   - **UserDataDir はプロファイル永続化のため従来どおり指定する**（セッションを保つ）
3. `func (b *Browser) closeCurrent()`（非公開）
   - `HijackRouter.Stop()` → `rod.Close()` → `launcher.Cleanup()` の順で確実に落とす
   - それぞれ nil チェックし、エラーは `slog.Warn` に留めて処理を続ける
     （落とせなかったことで起動し直しを諦めるほうが害が大きい）
4. `func (b *Browser) Relaunch(headless bool) error`（公開）
   - `mu` で排他し、`closeCurrent()` → `launch(headless)`
   - **Chromium は UserDataDir にロックを持つため、閉じた直後は再起動に失敗しうる。**
     `launch` に失敗したら 500ms 待って**最大3回**まで再試行する
   - 成功したら `Headless` を更新する
   - 失敗した場合はエラーを返す（呼び出し側が認証エラーとして扱う）
5. `func (b *Browser) Close() error`（公開）— 終了時用に `closeCurrent()` を公開する

> **Relaunch を呼んでよいのは認証処理の中だけ。**
> ポーリング中に呼ぶと `GetBattleLog` が使っている `Page` が差し替わって壊れる。
> 認証は `SelectGame` の中で、トラッキング開始前に完結するので競合しない。
> この制約を doc コメントに明記すること。

## 3. 修正仕様 B — 認証を「試す→必要なら表示ありでやり直す」構造にする

**対象: `app/pkg/tracker/sf6/cfn/client.go`**

現在の `Authenticate` を分割する。

### B-1. ログイン試行を関数に切り出す

```go
type loginResult int

const (
    loginOK         loginResult = iota // 認証済みになった
    loginNeedsHuman                    // 人間の操作が要る（画像認証など）
    loginFailed                        // 続行不能
)

func (c *Client) attemptLogin(ctx context.Context, email, password string,
    statChan chan tracker.AuthStatus) (loginResult, error)
```

- 現在の `Authenticate` の本体（ナビゲート・年齢確認・フォーム入力・送信・遷移待ち）をここへ移す
- **`defer recover()` はこの関数の中に置く**（rod の Must 系が panic するため）。
  panic を拾ったら `loginFailed` とエラーを返す
- 進捗の送出（10 / 30 / 50 / 65 / 100）は従来どおりこの中で行う

### B-2. 遷移待ちの分岐を変える

現在の待機ループを次のようにする。

- **ヘッドレスのとき**: `authGatewayGrace`（**5秒**）だけ待って、まだ
  `auth.cid.capcom.com` にいるなら **`loginNeedsHuman` を返して即座に抜ける**。
  30秒待つ意味は無い（人間が操作できないため）。ここを速くすることで
  表示ありへの切り替えが速くなる。
- **表示ありのとき**: 従来どおり `authGatewayWaitManual`（5分）まで待ち、
  毎秒 `authSolveCaptcha` のアクションを送る。時間切れなら
  `model.ErrAuthManualTimeout` で `loginFailed`。

### B-3. `Authenticate` は制御に徹する

```go
func (c *Client) Authenticate(ctx, email, password, statChan) {
    // browser == nil のチェックは現状のまま（既存テストが依存している）

    c.browser.SetAssetBlocking(false)
    defer c.browser.SetAssetBlocking(true)

    result, err := c.attemptLogin(ctx, email, password, statChan)

    if result == loginNeedsHuman && c.browser.Headless {
        // 人間の操作が要る。ウィンドウを出して最初からやり直す
        statChan <- action("authOpeningBrowser", 0)
        if rerr := c.browser.Relaunch(false); rerr != nil {
            statChan <- error(model.ErrAuthNeedsHeadful)   // 表示に切り替えられなかった
            return
        }
        c.browser.SetAssetBlocking(false) // 起動し直したので設定し直す
        result, err = c.attemptLogin(ctx, email, password, statChan)
    }

    // 認証の成否によらず、既定がヘッドレスならウィンドウを消す
    if c.browser.PreferHeadless && !c.browser.Headless {
        if rerr := c.browser.Relaunch(true); rerr != nil {
            // 消せなくても認証結果は活かす。警告ログのみ
            slog.Warn("failed to return browser to headless", ...)
        }
    }

    if result != loginOK { statChan <- error(...) ; return }
}
```

**注意点**

- `SetAssetBlocking(false)` は `Relaunch` のたびに設定し直す
  （新しい Browser 状態になるため）。`defer` の復帰も最後の状態に対して効くようにする
- ヘッドレスへ戻した後、ポーリングは新しい `Page` を使う。
  `Client` は `*browser.Browser` を保持していて `Page` はその都度参照するので、
  `GetBattleLog` が `c.browser.Page` を毎回読む形になっていることを確認すること
  （キャッシュしていたら直す）
- `loginNeedsHuman` でも `c.browser.Headless == false` なら（＝既に表示あり）
  再起動せず、そのまま `loginFailed` として扱う

### B-4. 定数

```go
authGatewayGrace = 5 * time.Second // ヘッドレス時、人間の操作要と判断するまでの猶予
```

`authGatewayWaitHeadless`（30秒）は不要になるので削除してよい。
`authGatewayWaitManual`（5分）と `authGatewayPollInterval`（1秒）は据え置き。

## 5. 受入条件（自動テスト）

Chromium の実起動を伴う部分は自動テストしない。**判断ロジックだけを対象にする。**

判断を純粋関数へ切り出してテスト可能にすること:

```go
// shouldEscalateToHeadful は、ログイン結果と現在のモードから
// 表示ありで起動し直すべきかを返す。
func shouldEscalateToHeadful(result loginResult, headless bool) bool

// shouldReturnToHeadless は、既定モードと現在のモードから
// ヘッドレスへ戻すべきかを返す。
func shouldReturnToHeadless(preferHeadless, headless bool) bool
```

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | `TestShouldEscalateToHeadful` | `loginNeedsHuman` かつヘッドレスのときだけ true。`loginOK` / `loginFailed` や既に表示ありのときは false |
| 2 | `TestShouldReturnToHeadless` | 既定がヘッドレスで現在が表示ありのときだけ true |

**既存テストを1件も壊さないこと。** 特に:
`TestTrackingSelectGame`（SF6 で `"unauthenticated: browser not initialized"` を期待）、
`TestShouldBlockRequest`、`TestSelectGameEmitsAuthActionRequired`、
`TestSelectGameReturnsOnAuthError`、`TestSelectGameDoesNotHangWhenChannelNeverCloses`、
および通信断対応の9件。

## 6. 検証コマンド

作業ディレクトリは `app/`。**`./...` は使わない**（root の `main` だけが Wails を import しており
Linux では GTK/WebKit ヘッダが要るため必ず失敗する）。

```bash
export GOMODCACHE=/tmp/gomodcache
export GOCACHE=/tmp/gocache
cd app
gofmt -l ./cmd ./pkg
go build ./cmd/... ./pkg/...
go vet   ./cmd/... ./pkg/...
go test  ./cmd/... ./pkg/... -count=1
```

## 7. 禁止事項

- **`app/main.go` を変更しない。** `NewBrowser(headless bool)` のシグネチャも変えない
- **CAPTCHA の自動突破に類する実装をしない。** `go-rod/stealth` にも手を加えない
- `wails build` / `bun install` / `npm install` / `bunx` / `npx` を実行しない
- 新規の外部依存を追加しない（`go.mod` / `package.json` を変更しない）
- 既存イベント名を変えない。追加するのは文言キーのみ
- **UserDataDir の指定を外さない**（セッションが消えて毎回画像認証になる）
- 認証情報をログにもテストにも出さない
- 改行は LF 固定
